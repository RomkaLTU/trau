# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

Trau is an autonomous, ticket-driven development loop shipped as a single static Go binary (`CGO_ENABLED=0`). It picks a ready tracker ticket (Linear/Jira/GitHub Issues, or an internal issue when no external tracker is configured), drives it through **build → handoff → verify → commit → PR → CI → merge** with one fresh AI-agent subprocess per phase, checkpoints after each phase, and resumes after any interruption.

Read `CONTEXT.md` first — it defines the domain vocabulary (**Provider / Model / Route / Fallback provider / Provider override**) and which near-synonyms to avoid. Use those terms exactly in code, comments, and tickets.

## Commands

```bash
make build                 # compile to bin/trau
make reset                 # rebuild + `trau hub restart` — humans only; refuses inside a trau run (TRAU_ACTIVE=1)
make test                  # go test -race ./...
go test -race ./internal/pipeline -run TestVerifyPause   # single test
make vet                   # go vet ./... (runs the make windows gate first)
make windows               # GOOS=windows go vet ./... — native-Windows compile gate, test files included (ADR 0023)
make lint                  # golangci-lint (installed separately)
make fmt                   # gofmt -w .
make dist                  # cross-compile release matrix into dist/
```

**Rebuild after every feature or ticket** so the change is actually testable. `make build` refreshes `bin/trau`. A running `trau serve` is a port-locked singleton with the SPA compiled into the binary, so it keeps serving the old code until restarted — autostart *reuses* a stale hub, it does not replace it. The web UI's footer shows `web`/`cli` versions; after a rebuild, confirm they reflect the new build (hard-refresh the browser, since the bundle's asset names are not content-hashed).

**The hub on :8728 is off-limits during agent runs.** If you are an agent spawned by trau itself (a build/verify/repair/cleanup phase — `TRAU_ACTIVE=1` is in your env), the hub on :8728 is the orchestrator that owns your run: restarting or killing it destroys the run's data channel and pauses the whole loop. The only supported restart is `trau hub restart`, which asks the running hub to re-exec the on-disk binary — never `kill`, never a port grab. `make reset` is `make build` plus that command and refuses outright while `TRAU_ACTIVE=1`; `trau hub restart --force` (the escape hatch for a hub whose API has wedged) refuses in the same situation, and while any loop is live. Both refusals are by design — do not work around them. To QA hub/web changes live, start an **isolated** hub from the dev binary and drive only that instance:

```bash
iso=$(mktemp -d) && TRAU_HOME=$iso/.trau HOME=$iso ./bin/trau serve --port 8799
```

Override BOTH `TRAU_HOME` and `HOME` so the isolated hub cannot see the real `~/.trau` databases. When done, kill only that pid. Never stop, restart, or "clean up" any process listening on :8728 — it was not started by you, even if a port probe makes it look recent. `make reset` is for humans doing interactive dev outside a run.

Commit messages follow Conventional Commits (`feat(scope):`, `fix:`, …) — release notes are generated from them (ADR 0002). Ticket IDs in commits/comments reference the project's own tracker tickets and act as the design changelog.

## Architecture

`cmd/trau/main.go` is the composition root (~2100 lines): flag parsing, layered config, and the builders (`buildRouter`, `buildTracker`, `buildPipeline`, `buildFallback`) that wire everything through injected interfaces. All modes (TUI session, headless, `--once`, `--dry-run`) converge on `runLoop(ctx, engine, ...)`, tested against the small `engine` interface. Subcommands: `doctor` (preflight) and `watch` (read-only transcript tail via `internal/vterm`).

The target repo is never the trau source tree — it resolves via `--repo` flag → `TRAU_REPO_ROOT` → cwd's git toplevel (ADR 0001). All `git`/`gh` operations act on the resolved target.

### Package seams (internal/)

- **pipeline** — the phase chain. Verify is a *cold, adversarial* pass: the verifier agent sees only the handoff brief (the `handoff` + `rubric` artifacts in the hub store) and the code on disk, never the build agent's reasoning. On verify failure: up to `MaxRepairs` repairs, then `MaxBugfixes` bugfixes, then quarantine. Error taxonomy is the core invariant (`classifyPhaseErr`): `GiveUpError` → quarantine + `needs-human` label; `PausedError` → provider rate-limit, work stays at checkpoint; `FaultError` → WIP pushed, resumable, loop stops; `CrossProjectError` → ownership refusal, nothing touched. Epic flow (`epic.go`) stacks sub-issues on an `epic/<ID>-*` integration branch. `lessons.go` keeps an append-only per-repo lessons ledger in the hub store (ADR 0008; the file-era `runs/memory/` JSONL survives only as the one-shot legacy importer's read side), recalled into later verify/repair prompts.
- **agent** — provider abstraction. `Runner.Run(ctx, prompt, label)` spawns a **fresh subprocess per call, never a resumed session** (that's what keeps verify cold). Providers register via `Spec` in `provider.go`; **nothing branches on provider name outside this package**. `router.go` dispatches per canonical phase key (`build/handoff/verify/repair/bugfix/cleanup/lintfix/commit/pick`); dynamic labels like `verify-retry2` collapse by prefix — new phase labels must keep their canonical prefix or they route to `pick`. Execution mode is **per provider, not a project-wide rule**: the claude pipeline provider is `ClaudeInteractive` — a real in-process PTY (`aymanbagabas/go-pty`, no tmux) with a result-file contract, never `-p` (the PTY transcript feeds `watch`/vterm, the auth sniffer, and terminal takeover, ADR 0018) — while codex/kimi run headless `-p --output-format stream-json`.
- **tracker** — hybrid direct-API + MCP-via-agent. Linear uses direct GraphQL when `LINEAR_API_KEY` is set, else the tracker's MCP through an agent prompt with sentinel-line parsing. Jira uses direct REST v3; with full REST credentials the tracker is deliberately rest-only (runner nil) so it can never silently switch to the MCP's different Atlassian identity. GitHub issues are MCP-only; PR/CI operations live in `pipeline` shelling to `gh`. The `internal` provider (ADR 0007) is the default when no external tracker is configured: it drives internal issues through the serve hub's HTTP API (`internal/hubclient`) — pick, status, labels, and comments — so the loop never opens the hub database; `buildTracker` autostarts the hub for it (ADR 0004).
- **state** — the per-ticket phase ranking (building→built→handed_off→verified→pr_open→merged, quarantined=9) and resume logic. Checkpoints are now DB rows the hub owns and migrates forward (ADR 0008); the file-era `.trau/runs/<ID>/state` `KEY=value` store survives only as the one-shot legacy importer's read side. **The phase ranking must stay stable across versions.**
- **config** — precedence: defaults < `~/.trau.ini` < `./trau.ini` < `<repo>/.trau.ini` < env (`TRAU_<KEY>` alias wins over bare `KEY`) < CLI flags (ADR 0016: repo config beats the home baseline). Config files are parsed KEY=value, never executed. All knobs are documented in `trau.ini.example`. Monorepo knobs resolved after a slice's diff is known (e.g. `LINT_FIX_CMD`) additionally check `<workspace>/.trau.ini` for the workspace owning the changed files (`config.WorkspaceOverride`, `agent.OwningWorkspaceDir`; ADR 0019) before falling back to the repo-root value.
- **event** — one JSON line per significant action to `.trau/runs/events.jsonl`; the durable source of truth. The TUI is display-only on top of it.
- **tui** — Bubble Tea **v2** (`charm.land/bubbletea/v2` imports, not `github.com/charmbracelet`). Two modes: `New` (dashboard renderer for headless-launched runs) and `RunSession` (persistent menu shell). The TUI talks to the backend only through the `tui.Actions` interface and never imports pipeline/tracker/agent wiring; the pipeline talks to displays only through `console.Renderer`.
- **webserver grill (Inbox Interview / Ask ahead)** — the one place hub code **deliberately runs `claude -p` headless** (`grillrunner.go`); do not "fix" it to interactive/PTY. Interview children are short-lived hub-spawned processes whose only I/O is their per-session MCP endpoint (`/api/v1/grill/{sid}/mcp`, tools `ask_user` + `finish_session`, `grillmcp.go`) — the web Inbox panel *is* their terminal, so there is nothing for a PTY to wrap, and the built-in AskUserQuestion tool doesn't exist in print mode. Turns chain via `--resume <session-id>`; a blocked `ask_user` streams SSE keepalives, parks on idle, and the user's later answer fires the resume turn. First-turn prompts + rule blocks are hardcoded in `grillprompt.go` (not in the ADR 0017 prompt catalog). Mechanism spec: `tasks/grilling-prd.md` (COD-865/877 research, verified on CLI 2.1.207).
- Supporting: **budget** (spend ceilings), **checks** (pluggable verify checks from `.trau/checks` YAML, executed by the verify agent), **skillrules** (repo-owned per-skill routing rules from `.trau/skills-rules.json` — `always`/`auto`/`manual` scopes matched against the ticket text at build and the slice's changed files after it; `agent.SkillResolver` folds them together with the config pins and the never-empty fallback chain, ADR 0021), **tokens** (normalized per-call token/cost JSONL; "Input" = non-cached portion so totals compare across providers; `CostUSD *float64` nil = unmetered), **usage/probe** (rate-limit windows for the HUD), **teamsync** (opt-in `TEAM_SYNC` sharing of lessons and settled-run summaries over the target repo's own git remote: the hub — never a loop child — force-pushes this machine's records as a parentless snapshot to `refs/trau/team/<writer-id>` and mirrors the teammates' back into `refs/trau/remotes/team/*`; refs only, never the working tree, and every failure is recorded for doctor rather than raised. Teammate runs are served from their own `team-runs` resource, never folded into `/runs`, so nothing that means *this machine's work* — the picker, the queue, the drain, the attention counts — can pick them up), **vterm** (reconstructs legible screens from raw PTY transcripts), **launchd** (the opt-in macOS LaunchAgent that keeps the hub up — `trau hub supervise` installs it with KeepAlive, the plist's `TRAU_SUPERVISED=1` makes a self-restart exit instead of racing launchd's successor for the port, ADR 0022), **sanitize**, **doctor**, **notify**, **timelog**, **logger**, **console**.

### Conventions and invariants

- **stdout is byte-stable** — all diagnostics (`--verbose`, `--debug`) go to stderr only; `--json` output must not change.
- Best-effort operations (logging, notify, timelog, gitignore maintenance) must **never abort the loop** — swallow-and-continue is the convention.
- Quarantine is idempotent.
- **The queue reconcile sweep never launches anything** (`drainer.reconcileQueue`, ADR 0022): on hub boot and on every drain arm it settles a paused or failed item *done* only on proof its work already shipped — a merged checkpoint, a tracker Done, or a merged PR — and leaves everything else exactly as it was. Auto re-attempts are a separate, opt-in path (`QUEUE_AUTO_RESUME`) and fire only for a blameless pause, never for a fault or a deliberate Stop.
- **`trau serve` exposure is fail-closed** (`internal/webserver`): a loopback bind is open and tokenless; any non-loopback bind requires `SERVE_TOKEN` — the server refuses to start exposed without one, and the whole API is gated behind `Authorization: Bearer <token>` (401 otherwise). Repo (un)registration is gated a second time: on a non-loopback bind it also requires `SERVE_ALLOW_REGISTER=1` (403 otherwise, naming the key), so a leaked token cannot widen the hub's startable-repo set. The blessed remote path is a private network / Tailscale, never a public port.
- Tests: table-driven with subtests; hand-rolled fakes shared across the package — `fakeGit`/`fakeRunner`/`fakeTracker`/`newTestPipeline` live in `internal/pipeline/verify_pause_test.go` and other test files embed/extend them. Golden files only in `internal/state/testdata`. No tests hit real providers or trackers; everything goes through the interface seams.
- **Spawned children carry no ambient memory** — every spawn seam builds its environment with `agent.ChildEnv`, which strips the host Claude Code session markers *and* sets `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Auto-memory is keyed to the git repo, not the session, and is shared with the operator's own sessions: a memorizing child would hand the build phase's reasoning to the cold verifier and persist prompt material (QA credentials) to a plaintext store trau doesn't own.
- **Every decision assumes Windows, Linux and macOS** — trau is developed on all three. OS-divergent behavior goes behind a shared contract with `*_unix.go` / `*_windows.go` implementations (`internal/proc`), never an OS branch at the call site; ADR 0023 requires unix behavior stay byte-identical while Windows reaches the same contract by a different mechanism. Never fix a Windows failure by skipping the test on Windows or by changing darwin/linux behavior — triage as production bug vs unix-assuming test and fix in the right layer. Acceptance criteria are "green on all three OSes." No PR-triggered test workflow exists (only GitGuardian), so nothing verifies linux/macOS before merge: `make -n <target> HOST_GOOS=linux` proves only the emitted command, so say "unverified" rather than implying it passed.
- **Every text file is LF, on every OS** — the repo carries the policy in `.gitattributes` (`* text=auto eol=lf`, plus an explicit `text eol=lf` on `**/testdata/**` and `binary` on image and font types), so a stock Git-for-Windows clone with the system `core.autocrlf=true` still checks out LF and the byte-compared fixtures match. Never commit CRLF, and never paper over a CRLF diff with a per-clone `core.autocrlf` setting — that fixes one machine and leaves the repo broken for everyone else.
- Architecture decisions live in `docs/adr/`; add an ADR for decisions of that scope.
